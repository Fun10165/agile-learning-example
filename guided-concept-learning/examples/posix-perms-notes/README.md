# POSIX 权限系统 · 敏捷学习笔记

## 知识范围

按这些假定来写；哪条与你不符，直接指出，以纠正为准：

- 你熟悉文件系统的基本行为：文件里放内容，目录里放文件（和别的目录）。
- 你知道一台机器可以同时有多个用户，用户可以被编进组。
- 对权限系统本身不需要任何使用经验——本版从它最初的问题讲起。

目标：讲清权限系统的判定规则——它由哪些需求逼出来、怎么算。

## 动机

一台机器上有多个用户，共享同一棵目录树。需要一条简单规则回答：

> 谁，能对这个文件做什么？

规则要足够便宜：每个文件只能花几个字节来记录权限，每次判定只做几次比较。这两个约束决定了表达方式：用固定大小的位图，把「身份 × 操作」编码成几个开关。

身份按与文件的关系取最常见的三档：文件的主人、主人所在的圈子、其余人。每增加一档身份就要多花三位，三档是开销最小的起点。

## 模型

每个文件带三样记号：一个属主（owner）、一个组（group）、九个权限位。

- 三类身份：属主（owner）、与属主同组的用户（group）、其他用户（others）。
- 三种操作：读取（r）、写入（w）、执行（x）。

同样是 rwx 三位，用在常规文件与目录上时含义不同：

| 位 | 常规文件 | 目录 |
|---|---|---|
| r | 读取文件内容 | 列出目录中的条目名称 |
| w | 修改文件内容 | 在目录中创建、删除、重命名条目 |
| x | 执行该文件 | 进入或穿越该目录 |

`ls -l` 的输出读法：

```
-rw-r--r--   ←  类型(-) + 属主(rw-) + 同组(r--) + 其他(r--)
drwxr-x---   ←  类型(d) + 属主(rwx) + 同组(r-x) + 其他(---)
```

类型位：`-` 常规文件，`d` 目录，`l` 符号链接。

九位也可以写成三个八进制数字：`rw- r-- r--` 写成 `644`，`rwx r-x ---` 写成 `750`。

一个完整的例子：

```
$ ls -l report.txt
-rw-r-----  1 alice dev  1024  report.txt
```

属主 alice 可以读取与修改；`dev` 组的成员可以读取；其余用户没有任何权限。

## 缺口清单

每个缺口标注类型，类型决定「解决它要做什么」：

- **内在矛盾**：已写下的规则在某个场景产生与需求冲突的行为（解决它要调和规则，或补一个补偿机制）；
- **未 spec 清楚**：机制在现实中已存在，模型文本尚未覆盖（解决它是补描述）；
- **扩展需求**：模型表达不了的、被需要的新能力（解决它是加结构）。

本版故意留下的不明确处：

1. **类别判定**（未 spec 清楚）：访问发生时，依据什么把访问者归入「属主 / 同组 / 其他」中的某一类？本版没有说明。
2. **多组归属**（未 spec 清楚）：一个用户同时在多个组里时，算不算「同组」？
3. **特权用户**（未 spec 清楚）：超级用户（root）看起来不受这九位约束，为什么？
4. **目录位的来历**（未 spec 清楚）：目录的 x 位含义与文件不同，这个设计从哪里来？（猜想：与路径逐级穿越有关）
5. **创建时的权限**（未 spec 清楚）：新建文件的权限从哪来？创建时并没有人手写 `644`。
6. **九位之外**（未 spec 清楚）：真实的 `ls -l` 输出里会见到 `s`、`t` 这类字符（setuid、sticky），它们不在这九位里，是什么？
7. **更细的规则**（扩展需求）：只有三类身份时，能不能表达比 owner / group / others 更细的控制？

这些缺口就是后续每一版的动机来源：每版挑一个缺口，引入回答它所需的最小机制。

## 概念覆盖审计

本版出现的概念 → 定义位置：

- 属主（owner）、组（group）、其他用户（others） → 「模型」开头与三类身份
- 权限位（九位）、读取 / 写入 / 执行（r / w / x） → 「模型」的两条列表
- 文件位与目录位的差异 → 「模型」的表格
- 类型位、八进制写法 → 「模型」的读法两段

按假定已知、不定义：文件、目录、用户、组、目录树。
