# 敏捷学习 · v0

这就是本仓库的学习模式。

## 知识范围

按下面的假定来写；哪条与你不符，直接指出，以纠正为准：

- 你学过一些东西，也忘过一些东西；
- 你会用 git 存版本，知道 `git log` 能看到每次提交；
- 你没有读过任何学习方法论，也不需要先读。

## 动机

有人要学一个东西。他读完一遍，过几天只记得名字。笔记写成一整篇，后来想改，不知道从哪里下手；想回看，也看不出当时是怎么想的。

要解决的问题只有一句：**让「理解一个东西」这件事能一步一步推进，每一步都能回看。**

## 模型

- 一份笔记，放进 git 仓库。
- 一次只推进一小步：每一版只回答一个问题。
- 每一版写成完整的一份笔记：读的人只看当前这一份，就能从头理解，不必翻历史。
- 每一版的提交信息写清楚这一版为什么出现：上一版解释不了的什么，把它逼了出来。
- 这一版还解释不了的东西，写在笔记末尾，作为下一版的候选。

例子：学「提交」时，第一版只有「提交是一次快照，记下谁在什么时候改了什么」。读完这一份，读者能说清提交是什么；「快照与把文件复制一份的差别」写进末尾的候选，留给下一版。

## 缺口清单

每个缺口标注类型，类型决定「解决它要做什么」：

- **内在矛盾**：「每一版都完整」与「一次只推进一小步」互相拉扯。完整要求把已有内容都写进来，笔记只会越来越长；模型没有说长到什么程度该停。
- **未 spec 清楚**：「一个问题」有多大，没有定义。「提交是一次快照」算一个，「快照怎么存」算不算另一个？
- **未 spec 清楚**：末尾的候选只写了「解释不了的东西」，没有说先做哪一条。

## 概念覆盖审计

- **笔记**：本版唯一的工作产物，一份 markdown 文件。
- **版本**：一次提交所对应的笔记状态。
- **完整**：读者只读当前版本、不翻历史，就能理解模型里的每个机制。
- **候选**：本版模型解释不了、留给下一版的问题。
- **提交信息**：随提交记录的一句话，写明「这一版为什么出现」。

## 目录

- `guided-concept-learning/`：教一个概念怎么讲清楚、怎么按版本迭代，本页这份笔记就是它的示例。
- `guided-course-outline/`：给一个主题排出学习顺序，只给章名与节名，再交给前一个 skill 逐节展开。
- `rigorous-anki-card-authoring/`：把学过的内容做成逐张审计、经批准后才出包的 Anki 卡组。
- `RULES.md`、`AGENTS.md`：作者的 agent 使用偏好，可选择性试用。
- `anki-open-template/`：Anki 模板的生成程序，以 submodule 形式引入，克隆后需要 `git submodule update --init` 才能看到内容。
